# Parallel Project Desktops — Edge-Case Review

Date: 2026-07-05 · Reviewer: Fable 5 (static code review; nothing here was run on-device — items marked ⚠ are code-verified logic, items marked ❓ carry an OS-behavior assumption).

Scope: findings **beyond** `docs/BACKLOG.md`. Known BACKLOG items are not re-reported.
Two BACKLOG items are in fact **already fixed** in code and can be struck:

- ~~"assert previous != target before posting"~~ → done, `RealDesktopEngine.swift:42` (early return when already on target).
- ~~"re-check IsSecureEventInputEnabled on verificationFailed"~~ → done, `RealDesktopEngine.swift:57`.

Also worth noting: the BACKLOG "reorder undetected" worry is **partly moot by design** — `SpacesProvider.resolveIndex` (`SpacesProvider.swift:17`) resolves UUID→ordinal at switch time, never cached, so reorder alone cannot land you on the wrong desktop. The remaining reorder gap is only the *badge* (a row can silently change which Ctrl+N it needs).

## Findings (sorted by severity)

| # | Edge case | Trigger | Current behavior (code) | Sev | Proposed handling |
|---|-----------|---------|------------------------|-----|-------------------|
| 1 | ⚠ **Empty/`"?"` Space UUID binds & collides** | User is on an untrackable Space (CONCEPTS.md documents macOS reporting `""` for churned desktops; the CGS bridge also fabricates `"?"` when the key is missing — `CGSPrivate.swift:52`) and saves a project, or recalibrates onto it | `saveCurrentDesktopAsProject` guards only `nil`, not `""`/`"?"` (`AppModel.swift:167`); `recalibrate` likewise (`AppModel.swift:304`). A project binds to `""`. A *second* untrackable Space also reports `""` → `store.project(forSpaceUUID:)` matches the wrong project; `contextBySpace[""]` merges resume context across physically different desktops; the drift detector thinks the project is fine whenever *any* untrackable Space exists | **P1** | Normalize at the provider boundary: `CGSSpacesProvider` should map `""`/`"?"` → `nil` (current) and drop them from `orderedUserSpaceUUIDs()`. Save/recalibrate then hit the existing nil path; give it a specific message: *"This desktop has no stable ID — recreate it or log out/in."* |
| 2 | ⚠ **Morning recap never fires again on day 2+** | Menu-bar apps run for weeks. `maybeShowMorningRecap` is called exactly once, from `init` (`AppModel.swift:57`) | The day-gate (`lastRecapDay`) is checked only at launch. Unless the user relaunches the app, F5 ("first app open of the day") never triggers after day 1 | **P1** | Observe `NSCalendar.dayChangedNotification` + `NSWorkspace.didWakeNotification`; run the same day-gated check there. ~6 lines. |
| 3 | ⚠ **Resume context lost on quit / shutdown / logout** | User works on a project desktop, then quits the app (or shuts down) without switching Spaces | Context is persisted only inside `activeSpaceDidChange` (`AppModel.swift:101-104`). The in-memory `contextBySpace` cache dies with the process → after relaunch, the resume card shows the *previous* session's stale context | **P1** | Persist the current Space's context in `applicationWillTerminate` and on `NSWorkspace.willSleepNotification`. The `persist(_:toSpaceUUID:)` plumbing already exists. |
| 4 | ⚠ **Switch-failure feedback is invisible** | Any failed switch: Secure Input, disabled shortcut, ordinal >9, verification timeout | `enter()` writes `status` (`AppModel.swift:320-327`) — but selecting a project closes/obscures the popover, and on failure you stay on your desktop with **no visible signal**. Every carefully-built engine failure mode (`describeSwitch`, `AppModel.swift:504`) dead-ends in a hidden string | **P1** (UX-critical, see ux-review.md) | Route non-`.switched` results to a transient floating toast (reuse `PanelFactory` — the infrastructure exists in `FloatingPanels.swift`). Keep `status` as the in-popover echo. |
| 5 | ⚠ **`ProjectStore.update()`/`remove()` swallow save failures** | Disk full, permissions, Application Support gone | `save()` returns `Bool` precisely so callers can surface failure, but `update`/`remove` ignore it (`ProjectStore.swift:63-73`). UI confirms "Renamed…" while disk still has the old state → silent revert on next launch | **P2** | Make `update`/`remove` return `Bool`; `AppModel` surfaces *"Couldn't save — check disk"* like `add` already does. |
| 6 | ⚠ **Cap 16 vs. 9 keyable ordinals** | User saves an 10th–16th project | `maxProjects = 16` (`ProjectStore.swift:19`) but the engine hard-fails ordinals >9 (`RealDesktopEngine.swift:45`). Projects 10+ save fine and are *permanently* unswitchable by click | **P2** | At save time, if the desktop's ordinal >9, warn in status: *"Saved — but desktop 12 has no Ctrl+number shortcut; it can't be switched to."* Pairs with the BACKLOG keyability badge. |
| 7 | ⚠ **Rapid double-switch: two engines race** | User clicks project A then B within ~1.5s (or double-clicks) | Each `enter()` spawns an independent `Task` (`AppModel.swift:322`); two `postControlNumber` events interleave; both bounded polls run concurrently and each can (mis)credit the other's landing. BACKLOG covers the `status` string race, not the double key-post | **P2** | Keep a single in-flight switch handle in `AppModel`; either ignore clicks while switching or cancel-and-replace. |
| 8 | ❓ **Multi-monitor capture pollution (even without "separate Spaces")** | Two displays, one Spaces set; user saves a project | `.optionOnScreenOnly` (`AppInspector.swift:22`) returns windows on **all** screens → the blueprint absorbs the other monitor's apps; passive frame recording likewise | **P2** | Filter windows by intersection with the primary display's bounds, or pipe PIDs through `CGSCopySpacesForWindows` (the caveat comment in `AppInspector.swift:14-17` already anticipates this). |
| 9 | ⚠ **Uninstalled blueprint app reported as "open on another desktop"** | App in blueprint was uninstalled; user hits "Bring up here" | Launch failure lands in `elsewhere` (`AppModel.swift:446-447`) → message says *"…open on another desktop (can't relocate)"* — factually wrong, and `localizedName` lookup returns nothing so it degrades to a bare count | **P2** | Separate `failedToLaunch` from `elsewhere`; message: *"couldn't launch X — is it still installed?"* |
| 10 | ❓ **Save while in a fullscreen Space** | User is in a fullscreen app (type-4 Space) and opens the menu → the "Save this desktop as…" field is offered | `currentSpaceUUID` (`CGSPrivate.swift:58`) reads `Current Space` without a type check — if the active Space is fullscreen, the project binds to a Space that **evaporates when the app leaves fullscreen** → guaranteed drift. (`userSpaces` filters type 0 for *ordering*, but not for *current*) | **P2** | Verify on-device; if confirmed, hide the save field (and block recalibrate) when the current Space's type ≠ 0: *"Fullscreen apps can't host a project."* |
| 11 | ❓ **Minimized windows mislabeled** | Blueprint app's only window is minimized on *this* desktop; "Bring up here" | `windowCount` counts AX windows including minimized (`AppInspector.swift:53`) → >0 → treated as "has windows on another desktop (can't relocate)" instead of just de-minimizing | **P3** | Check `kAXMinimizedAttribute`; treat all-minimized like windowless (activate reopens here). |
| 12 | ⚠ **Pinned Chrome profile later deleted** | User pins "Profile 3", then removes it in Chrome | `isValidFolder` validates *format* only (`ChromeProfiles.swift:27`). Chrome, given `--profile-directory=Profile 3` for a folder that's gone, **creates a fresh empty profile** → links open logged-out in a ghost profile | **P3** | At plan time, validate the pinned folder against the loaded `chromeProfiles` cache; fall back to `lastUsedFolder` + status note. |
| 13 | ⚠ **Stale resume title within one app** | User works 3 hours in one app, switching documents, then leaves | Context refreshes only on `didActivateApplication` (`AppModel.swift:77-84`) → the captured `windowTitle` is from when the app was last *activated*, not when the user *left* | **P3** | Also refresh in `activeSpaceDidChange` **before** persisting the outgoing context — one call, but it must read the outgoing Space's data before the switch completes; if timing makes that unreliable, add a slow (60s) refresh timer. |
| 14 | ⚠ **Duplicate project names** | Save two desktops as "Sales" | Allowed silently; search shows two identical rows (`ProjectSearch` has no disambiguator), status messages ambiguous | **P3** | Suffix in UI ("Sales · Desktop 4") or warn on save. |
| 15 | ⚠ **Delete is one click, no confirm, no undo** | Slip in the ••• menu (Delete sits directly under a divider) | `delete()` removes instantly (`MenuBarListView.swift:317`, `AppModel.swift:213`) — blueprint, links, checklist, notes all gone | **P3** | Cheapest: keep the last deleted `Project` in memory and make status actionable: *"Deleted 'Sales' — Undo"*. |
| 16 | ⚠ **Recap day marked "shown" even if instantly dismissed / OS-day quirks** | Recap fires while user closes it unread; or timezone change replays/skips a day | `lastRecapDay` set before showing (`AppModel.swift:128`); `DateFormatter` uses local tz | **P3** | Acceptable for v1; note only. |
| 17 | ⚠ **Save offered while drifted projects exist** | Project's desktop was deleted; user makes a new desktop and re-saves the same workstream | New project created; the drifted one lingers with all its links/checklist orphaned | **P3** (UX) | When drifted projects exist and the current desktop is unclaimed, offer *"Recalibrate 'Sales' to this desktop"* alongside the save field. |

## Genuinely unsolvable within macOS constraints (documented, not fixable)

- **Relocating an already-windowed app to this Space** — every path (openApplication, AppleScript, AX Dock menu) activates-and-travels (`AppModel.swift:458-462`, SPIKE notes). Current "report, don't yank" behavior is correct.
- **Default-browser link placement on a cold switch** — window is born on whatever Space is active at creation; the 1.5s settle + bounce warning (`AppModel.swift:397`) is the honest ceiling without the Chrome-profile recipe.
- **Desktops beyond ordinal 9** — no symbolic hotkey exists; only mitigable (badge/warn), not solvable, until the emulated-workspace engine.
- **Secondary-display Spaces** — deliberately out of v1 (spike selected B-global); the primary-display-only provider (`CGSPrivate.swift:62`) is a scope decision, not a bug.
